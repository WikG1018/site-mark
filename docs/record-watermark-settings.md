# 项目、记录、水印与设置详细设计

> 状态：当前设计
> 适用版本：v1.0.8 当前版本

## 1. 首页与项目

首页以项目为第一层入口，提供状态筛选、项目搜索、全部记录、总设置和新建项目。默认
显示进行中项目，搜索覆盖进行中、已完成和已归档三个状态；退出搜索后恢复原筛选和滚动
位置。项目可独立置顶，卡片显示状态、记录数和最近拍摄时间。每个项目保存自己的名称、
说明、水印参数、生命周期和置顶状态；拍摄记录通过项目 ID 与所属项目关联。

项目、全部记录、设置通过覆盖在内容上方的紧凑悬浮 Dock 切换。三个根页面分别保留导航、
搜索、筛选和滚动状态，但只有当前页面参与绘制，避免访问全部记录后从项目详情返回时隐藏
照片列表短暂闪现。Dock 的选中背景完整包住图标和文字。

已完成和已归档项目禁止新拍摄，但已有记录仍可查看、编辑、导出和清理；重新启用后恢复
拍摄。标记完成或归档前，处理中记录会阻止操作，失败记录需要明确确认。

新建项目必须通过两层唯一性检查：显示名称忽略首尾空白、连续空白和英文大小写；
安全文件名键还会把文件系统禁止字符统一替换。已有重复项目不迁移，只阻止后续创建
新的冲突项目。

总设置中的水印参数是“新建项目默认值”，只在创建项目时复制，不追溯修改已有项目。
已有项目的水印样式必须进入项目水印设置单独修改。

## 2. 连续拍摄、最近建议与命名模板

现场记录字段包括：

- 工程部位；
- 工作内容；
- 拍摄人；
- 可选备注。

同一项目完成一张拍摄后，下一张自动保留工程部位、工作内容和拍摄人，备注清空，
避免把上一张的特殊说明误带入新记录。相机取消时保留当前表单内容，不创建可见记录。
系统相机返回后表单不等待水印生成，用户可以立即继续拍摄。

工程部位、工作内容和拍摄人的输入框获得焦点时，可显示当前项目最多 3 个最近建议；
“更多”读取该字段最多 20 个去重值并支持过滤。建议直接来自当前项目现存拍摄记录，
不建立永久历史词库：`pendingCamera` 排除，`captured`、`rendering`、`ready` 和 `failed`
均可作为来源。点击建议只替换当前字段；读取失败只隐藏建议，不阻止手动输入和拍照。

命名模板只属于创建它的项目，保存模板名称、工程部位、工作内容和拍摄人，不保存备注。
应用模板替换三个必填字段并保留当前备注，可撤销最近一次应用。模板不会自动应用、不会
触发拍照，也不会随以后编辑记录而改变。每项目最多 100 个；项目删除时级联删除模板，
不同项目可以使用相同模板名称，不能浏览或应用其他项目的模板。

模板名称先执行 Dart `trim()`，再把 `RegExp(r'\s+')` 识别的连续 ECMAScript/Unicode
空白折叠为一个 ASCII 空格；唯一键只将 ASCII `A-Z` 转成小写。工程部位、工作内容和
拍摄人只执行 `trim()`，内部空白不折叠。列表按 `updatedAt DESC, name ASC` 排序。

模板名称最长 80 个 Unicode 标量，工程部位 160、工作内容 240、拍摄人 80；四个可编辑
值均拒绝 U+0000。Dart 服务以 `runes.length` 校验。Rust 归档以 `chars().count()` 校验，
并分别显式复刻 Dart `trim` 和正则 `\s` 集合：U+0085 仅在边缘被 trim，U+FEFF 还会在
名称内部折叠，U+200B 保留。SQLite 只以 `length()`、NUL CHECK 和项目内 `name_key`
唯一约束兜底，不执行规范化。模板创建、重命名、删除和恢复批量写入均使用数据库事务；
错误保留当前表单或弹层输入，并提供安全的重试提示。

## 3. 记录列表与筛选

项目详情显示本项目记录；首页“全部记录”显示跨项目记录。两处复用同一记录卡片、
缩略图、状态标记、关键词搜索、日期筛选和分页组件。搜索框输入停止 250 ms 后才提交
查询；在搜索状态按系统返回键会关闭搜索并清除关键词，而不是离开记录页。

筛选条件采用项目、年、月、日级联规则：

- 项目详情固定当前项目，只显示年/月/日；
- 全部记录增加项目条件；
- 年、月、日控件使用 44dp 高、10dp 圆角的紧凑矩形并排，文字以整个按钮为基准居中；
- 上级条件改变时清除不再有效的下级条件；
- 选项只列出实际存在记录的项目和日期；
- 日期按手机本地时区的 `capturedAt` 计算，缺失时回退 `createdAt`；
- 结果按 `capturedAt ?? createdAt` 倒序。

日期选项和匹配数量由数据库根据当前项目、日期和关键词条件计算，只显示实际存在的值。
关键词按空白拆分；每个词可匹配项目名称、工程部位、工作内容、拍摄人、备注、照片编号
或地址，多个词必须同时匹配。关键词中的 `%`、`_` 和反斜杠按普通文字处理。

记录列表使用 50 条的游标分页，以排序时间和记录 ID 作为稳定游标；接近末尾 8 条时
预取下一页。已加载记录会持续刷新状态；列表在顶部时，新匹配记录会自动刷新进入列表，
已向下滚动时显示“新记录”操作，用户确认后回到顶部并刷新。已删除的已加载记录会刷新
列表，避免继续显示失效项目或记录。

记录卡片不再直接显示冗长的完整照片编号，而显示`yyyy-MM-dd · 当日序号`；完整编号仍在
详情页中保留。旧编号和新编号都采用相同的短列表标题。

## 4. 预览、详情与编辑

记录卡片根据处理状态选择图片：

- `ready`：显示最终水印图；
- `captured`/`rendering`：优先显示原图并叠加等待或处理中状态；
- `failed`：显示可用图片和错误状态；
- 文件不存在：显示占位图。

详情页显示大图、现场字段、照片编号、拍摄时间、定位结果、文件大小、原图状态和
SHA-256；图片可进入全屏缩放查看。详情操作包括查看原图、删除原图、再次保存水印图、
重新处理和删除整条记录，按钮是否可用由当前状态和文件是否存在决定。

从记录列表到详情页、再进入全屏，均使用同一记录的 Hero 标识（列表 → 详情 → 全屏）。
全屏先显示当前图片，再按打开时的完整查询条件按需加载时间上相邻的记录。相邻记录在当前
选定的图片来源不可用时会推进相邻查询游标但不加入图片序列。接近已加载图片两端时会
预取相邻批次。

列表进入编辑模式后可以多选记录，并执行：

- 导出所选记录；
- 再次保存所选水印图到相册；
- 清理所选记录的私有原图；
- 删除所选原图、水印文件、相册成片和数据库记录。

选择框覆盖在缩略图左上角，不改变缩略图和正文的横向起点；底部悬浮操作栏显示每项操作
的图标和文字，在 360dp 宽度和大字体下保持单行且不遮挡最后一条记录。

全选按钮从数据库读取完整当前筛选结果中的可编辑记录，不限于已经加载的页面；再次点击
会取消全选。`captured` 和 `rendering` 状态不参与全选。大量所选 ID 在重新检查资格时按
SQLite 参数上限分块查询；状态变化或筛选变化后会重新核验，避免对已不符合条件的记录
执行操作。

执行破坏性操作前必须显示清楚影响范围，处理中记录不得进入会与后台任务竞争的编辑或
删除流程。

## 5. 水印内容

水印卡片可显示：

- 项目名称；
- 工程部位；
- 工作内容；
- 拍摄人；
- 拍摄时间；
- 地址、坐标和精度（存在时）；
- 备注（存在时）。

照片编号不显示在水印上，但继续保存在数据库、JPEG 文件名、CSV 和 JSON manifest。
水印语言在拍摄时按当前界面语言写入记录，后台处理即使晚于语言切换，也使用拍摄时的
语言生成中文或英文标签。

## 6. 水印布局和参数

Rust 根据实际文字测量卡片宽度，不使用固定的照片宽度比例作为最终宽度。短内容得到
更窄的卡片，长内容在安全上限内扩展；高度由实际行数、字号、行高和 padding 计算。
布局必须在横拍、竖拍和支持的最低分辨率内避免越界与裁切。

当前可调参数：

| 参数 | 范围或选项 | 生效范围 |
| --- | --- | --- |
| 位置 | 左下、右下 | 项目或新项目默认值 |
| 透明度 | 20%–95% | 项目或新项目默认值 |
| 字体比例 | 80%–160% | 项目或新项目默认值 |
| 强调色 | 绿色、蓝色、橙色 | 项目或新项目默认值 |

不提供自由拖拽、任意字体、任意模板脚本或把编号重新加入水印的开关，以保持不同项目
和不同设备上的输出稳定性。

## 7. 文件命名

照片编号格式为：

```text
{安全化项目名称}-SM-{yyyyMMdd}-{全应用当日序号}
```

项目名称中的空白、控制字符、路径分隔符以及 Windows 禁止文件名字符会替换为下划线；
括号、点号、连字符和 `&` 等非禁止字符可以保留。序号按手机本地日期在所有项目之间
统一递增，从而在不写入项目 UUID 的情况下保持新文件名唯一。最终 `.jpg` 文件名按
UTF-8 计算不超过 255 字节。该规则只作用于新拍照片，旧记录和旧文件不重命名。

## 8. 总设置、备份与诊断

总设置包括：

- 外观：跟随系统、浅色、深色、动态颜色和应用强调色；
- 语言：跟随系统、简体中文、English；
- 新项目水印默认位置、透明度、字体比例和强调色；
- SiteMark 应用内数据占用合计及私有原图、私有成片、本地导出、数据库和其他文档明细；
- 存储刷新、拍摄记录管理入口和本地导出 ZIP 清理；
- 备份与恢复：单项目/多项目选择、可选私有原图、恢复文件选择；
- 诊断与反馈：本机 7 天、2 MB 上限的隐私安全事件记录，主动确认后生成分享 ZIP；
- 定位与通知：管理前台定位授权和后台处理完成通知；
- 关于：应用版本、离线和隐私说明、许可证、第三方声明及 GitHub 代码仓库链接。

存储统计不包含系统相册。清理本地导出前必须二次确认，只删除应用私有 `exports` 目录
中的 ZIP；已分享副本、相册照片、原图和记录不受影响。

“GitHub 代码仓库”显示可识别的仓库地址，点击后交给系统浏览器处理。应用自身不因该
入口获得网络权限。

诊断页面必须常驻显示隐私说明，分享前再次列出包含与排除内容。诊断包不允许包含照片、
项目名称、工程字段、人员、位置、文件路径、照片编号、哈希、原始异常或堆栈，也不得
自动上传或引入网络权限。

单项目备份和多项目 bundle 内的项目 ZIP 使用项目归档 schema v5，保存生命周期、置顶和
当前项目模板，并继续读取 v1/v2/v3/v4 旧项目 ZIP；多项目外层 bundle schema 仍为 v1。
旧项目 ZIP 恢复为进行中、未置顶和空模板列表。恢复前同时校验生命周期、模板数量、
唯一性、字段和时间，项目、记录、模板受恢复所有权令牌约束；数据库或文件步骤失败会
回滚隐藏项目、暂存文件和已规划目标文件。

恢复内部以 `ProjectRestoreStateException.failure` 的 `ownershipLost` 和
`templateSetMismatch` 区分状态不一致，bundle 和界面层统一归类为 `general` 并显示
通用恢复失败。当前持久化诊断覆盖备份、恢复与删除操作结果；事件仍不得包含项目名称、
模板内容、路径、SQL 或原始异常。
