# UI 流畅度优化实施说明

## 目标

在不增加图片内存压力和无意义动画的前提下，改善列表加载、图片转场和全屏浏览体验。

## 本次落实

- 项目列表、全部记录、项目内记录统一使用 Skeletonizer 表达首次加载。
- 保留 Flutter 列表自带的按需构建，不手动扩大图片列表缓存。
- Hero 解码宽度根据屏幕宽度和 DPR 计算，最高限制为 2048 像素。
- 系统开启“减少动画”后，跳过路由、Hero 和局部切换动画。
- 非 Hero 图片淡入缩短为 200 ms。
- 全屏查看支持左右切换当前筛选结果中的相邻照片。
- 相邻照片按需解析，只有滑到该页时才读取文件；不会在打开全屏时扫描整个项目。
- 全屏来源跟随详情页当前选项：查看水印图时切换水印图，查看原图时切换原图。
- 项目内记录和“全部记录”入口使用同一套相邻照片逻辑。
- 每个全屏页只注册一个缩放监听器，离开页面时完整释放。

## 明确不做

- 不为转换形式而把所有 `ListView` 改写成 Sliver。两者都采用惰性构建，项目内记录本身已经是 `SliverList`。
- 不手动增加 `cacheExtent`。图片列表扩大预加载范围会提高解码内存占用，缺少真机性能数据时收益不确定。
- 不额外包裹 `RepaintBoundary`。Flutter 的列表代理默认已经给子项添加重绘边界，重复包裹会增加图层。
- 不给所有卡片增加按压缩放。现有 Material Ink 反馈已经清楚，额外缩放会增加动画和重建。
- 暂不分页。当前数据库流和列表均为惰性构建；分页应在真机数据量证明查询或内存成为瓶颈后单独设计。

## 验收

- `flutter analyze` 无问题。
- 全部 Flutter 测试通过。
- Rust 格式、Clippy 和测试通过。
- Android 单元测试及 Debug APK 构建通过。
- 全屏支持初始定位、左右切换、双击缩放、缩放时禁止翻页、下滑退出。
- 原图已清理时不会把不存在的原图作为相邻照片来源。
