# SiteMark v0.10 项目生命周期管理设计

> 状态：已确认设计
> 日期：2026-08-03
> 依赖基线：`main` / `0.9.0+13`
> 目标版本：`0.10.0+14`

## 1. 目标

为工程项目增加“进行中、已完成、已归档”三个明确阶段，使首页在项目积累后仍保持整洁，并防止已结束项目继续误拍。

本次同时补齐置顶、按最近拍摄排序、跨状态搜索和备份恢复契约。项目配置复制、标签、分组、自动归档、批量改变状态均不在本次范围。

## 2. 生命周期规则

项目状态固定为：

- `active`：进行中，可以拍摄和执行全部现有操作；
- `completed`：已完成，禁止新拍摄，仍可查看、编辑、筛选、导出、备份及管理已有照片；
- `archived`：已归档，默认不出现在首页，禁止新拍摄，仍可从归档项目入口查看和管理已有内容。

允许的状态转换为：

| 当前状态 | 可执行操作 | 结果状态 |
| --- | --- | --- |
| 进行中 | 标记完成 | 已完成 |
| 进行中 | 归档 | 已归档 |
| 已完成 | 重新启用 | 进行中 |
| 已完成 | 归档 | 已归档 |
| 已归档 | 恢复使用 | 进行中 |

不提供“归档后直接恢复为已完成”。需要继续管理但不拍摄时，先恢复为进行中，再标记完成。

置顶状态与生命周期相互独立，三个状态都可以保留置顶标记；置顶只影响当前筛选列表的排序。

## 3. 状态变更保护

状态变更由独立生命周期服务在数据库事务内完成，不能只依赖界面隐藏按钮。

标记完成或归档前，统计项目内拍摄记录：

- 存在 `pendingCamera`、`captured` 或 `rendering` 时，阻止操作并显示尚有多少张正在拍摄或处理；
- 不存在处理中记录、但存在 `failed` 时允许继续，但必须二次确认并显示失败数量；
- 没有处理中或失败记录时直接执行。

服务在提交前重新读取数据库中的当前状态，并使用预期状态作为条件更新。状态已被其他页面改变时，刷新数据并提示用户，不以旧界面状态覆盖新值。

创建待拍记录的事务必须再次验证项目为 `active`。即使界面状态过期或从深层链接进入，也不能为已完成或已归档项目启动新拍摄。

## 4. 数据模型与迁移

Drift schema 从 10 升到 11，`projects` 增加：

- `lifecycle_status TEXT NOT NULL DEFAULT 'active'`；
- `is_pinned INTEGER NOT NULL DEFAULT 0`。

Dart 使用 `ProjectLifecycleStatus` 枚举及 Drift 转换器，数据库只接受 `active`、`completed`、`archived`。旧数据库迁移后，现有项目全部为进行中且未置顶。

新增项目汇总查询，返回项目本身及：

- 可见拍摄记录数量，不统计 `pendingCamera`；
- 最近拍摄时间，取非 `pendingCamera` 记录的 `MAX(COALESCE(captured_at, created_at))`。

项目排序固定为：置顶优先、最近拍摄时间倒序、项目创建时间倒序、项目 ID 作为稳定兜底。没有照片的项目按创建时间参与排序。

恢复流程持有的临时项目继续从普通列表、搜索、状态数量和汇总查询中排除。

## 5. 首页与项目页

首页默认只显示进行中项目。标题区域提供紧凑的状态筛选入口，点击后使用底部弹层选择“进行中、已完成、已归档”，不增加一排大型椭圆按钮。

项目卡片显示：

- 项目名称和说明；
- 照片数量；
- 最近拍摄时间，没有照片时显示“暂无拍摄记录”；
- 小型状态标识；
- 置顶标识。

卡片更多菜单提供与当前状态相符的操作：置顶或取消置顶、标记完成、归档、重新启用。原有重命名和删除入口保留。

首页搜索覆盖全部生命周期，不受当前状态筛选限制；搜索结果必须显示项目状态，避免用户误以为项目已丢失。退出搜索后恢复原状态筛选和滚动位置。

已完成或已归档项目的详情页显示状态提示，隐藏拍摄按钮并提供“重新启用”。已有记录继续支持查看、编辑、筛选、导出、再次保存、删除水印照片、清理或删除原图等现有操作。

## 6. 备份与恢复

单项目 ZIP schema 从 4 升到 5，项目清单新增生命周期状态和置顶字段。Rust 与 Dart 都必须验证：

- 生命周期值只能是 `active`、`completed`、`archived`；
- 置顶字段必须是布尔值；
- schema 5 缺少字段或字段类型错误时拒绝恢复，不写入半成品数据。

恢复规则：

- schema 1 至 4 的备份恢复为进行中、未置顶；
- schema 5 完整保留备份时的生命周期和置顶状态；
- 已归档项目恢复后仍为已归档，不自动改为进行中；
- 多项目备份外层 bundle schema 继续为 1，只升级其中的单项目 ZIP；
- 原有恢复归属标记、事务提交、失败回滚和重名处理保持不变。

恢复结果需显示各状态项目数量。恢复结果包含归档项目时提供“查看归档项目”入口，避免恢复成功后在默认首页看不到项目。

## 7. 空状态、返回与动画

三个状态分别使用明确空状态：

- 进行中为空：提示新建项目或从备份恢复；
- 已完成为空：提示尚无已完成项目；
- 已归档为空：提示尚无归档项目。

从状态弹层返回只关闭弹层；从搜索返回先退出搜索；项目详情返回仍回到进入前的筛选和滚动位置。现有 Hero 图片转场、减少动画无障碍设置和记录页返回规则不修改。

## 8. 文案与本地化

新增状态、操作、确认、阻止原因、恢复结果和空状态均提供中文与英文文案。大字体下状态标识和卡片统计信息允许换行，不能与更多菜单或项目名称重叠。

## 9. 测试与验收

自动化测试覆盖：

- schema 10 到 11 迁移和全新建库；
- 三种状态的合法转换、过期状态冲突、处理中阻止和失败记录确认；
- 数据层禁止已完成或已归档项目创建待拍记录；
- 置顶、最近拍摄时间、空项目和稳定兜底排序；
- 状态筛选、跨状态搜索、返回、空状态和隐藏拍摄按钮；
- 单项目 ZIP schema 1 至 5、非法字段、状态与置顶原样恢复；
- 多项目备份混合状态恢复及归档项目入口；
- 中文、英文、大字体和系统减少动画模式。

完成后必须通过 `flutter analyze`、全部 Flutter 测试、Rust 格式检查与测试、Android 单元测试和 debug APK 构建。

## 10. 文档与版本

实现完成后同步更新 README、当前产品架构、备份恢复相关说明、决策记录和关于页版本号。目标版本为 `0.10.0+14`，本次只创建可合并 PR，不直接发布版本。

## 11. 明确不做

- 不复制或克隆项目配置；
- 不增加标签、分组、自动完成、自动归档或批量状态变更；
- 不增加云同步、账号体系或跨设备在线状态；
- 不改变已保存到系统相册照片的处理规则；
- 不在本功能中实现诊断中心、自修复或备份健康检查。
