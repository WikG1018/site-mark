# SiteMark 界面重构设计

> 状态：已确认设计
> 日期：2026-08-04
> 依赖基线：`main` / `0.10.0+14`

## 1. 目标与范围

本次重构统一一级导航、项目与记录页面、拍摄表单、照片详情和设置首页，减少顶部图标堆叠、大型筛选按钮、重复入口及不符合预期的返回行为。

视觉采用较明显的半透明玻璃风格，但必须保证户外强光、大字体和性能较弱设备上的可读性与流畅度。本次不改变照片处理、备份格式、项目生命周期和数据模型的业务规则。

## 2. 导航与返回

一级页面固定为“项目、全部记录、设置”，使用底部悬浮玻璃 Dock。三个页面切换时保留各自的滚动位置、搜索和筛选状态。

- “新建项目”按钮只在项目首页显示；
- 项目详情、拍摄表单、照片详情等二级页面不显示 Dock；
- 二级页面顶部只保留返回、搜索或更多等必要入口；
- 重命名、备份、生命周期、删除等低频操作进入带文字说明的底部操作面板；
- 系统返回键依次关闭弹层、退出搜索、退出筛选、取消编辑或批量选择，临时状态全部清除后才返回上一页；
- 返回上一页时恢复进入前的列表位置和状态，不重复弹出上一步页面。

## 3. 项目首页与项目详情

项目首页使用玻璃项目卡片，展示项目名称、生命周期状态、照片数量、最近拍摄时间和最近照片缩略图。卡片整卡进入项目详情，搜索放在页面顶部。原有进行中、已完成、已归档筛选继续保留，但改为紧凑入口和底部选择面板，不恢复大型椭圆按钮。

进入搜索后只保留输入框内的清空按钮；系统返回键先退出搜索，标题与列表恢复时不得跳动。新建项目按钮独立悬浮在右下角。

项目详情顶部只保留返回、搜索和更多。项目摘要压缩高度，突出名称、状态和记录数量。记录按日期分组，卡片显示短编号、关键现场信息、处理状态和原图是否保留。

点击“选择”或长按记录进入批量模式；全选再次点击必须取消全选。项目水印设置、备份、重命名、生命周期管理和删除统一放入更多操作面板。

## 4. 全部记录与筛选

全部记录页顶部保留搜索和“选择”。默认只显示一个筛选入口；点击后从底部展开项目、年、月、日四项筛选。

- 已生效条件显示为可单独移除的小标签；
- 记录按日期分组，日期标题滚动时短暂吸顶；
- 搜索、筛选面板和批量模式互斥；
- 批量模式沿用项目记录页的全选、导出、保存和删除规则；
- 大字体或窄屏下标签可横向滚动或换行，不能与按钮、箭头重叠。

## 5. 拍摄页面

拍摄表单压缩为单屏结构：工程部位、工作内容和拍摄人三个必填项始终可见，最近使用值紧邻对应输入项，备注默认折叠，拍摄按钮固定在底部安全区域上方。

定位说明只在首次需要解释或授权尚未处理时出现；用户授权、拒绝或确认后不再长期占位。拒绝定位仍允许拍摄。

连续拍摄时保留三个必填值，只清空备注。拍照后立即允许继续发起下一次拍摄，水印处理继续在后台执行，处理状态自动刷新。

## 6. 照片详情与全屏查看

详情页标题使用“日期 + 当日编号”，完整文件名放入“文件信息”。顶部只保留返回和更多。

- 照片上方保留“成片 / 原图”切换；
- 照片下方使用“现场记录 / 文件信息”双页签；
- 点击照片进入全屏查看，可左右滑动相邻照片；
- 列表、详情和全屏之间保留 Hero 飞行动画；
- 编辑、删除原图、删除整条记录进入带文字说明的操作面板，危险操作明确说明影响范围。

Hero 起点、飞行内容和落点必须使用同一张已解码预览图；不得在动画结束时切换到失败占位或重新加载造成闪烁。原图已删除时不得回退读取原图。

## 7. 设置首页

设置作为一级页面，不显示返回箭头。首页采用三组紧凑玻璃列表：

- 拍摄与记录：新建项目水印默认值、定位、完成通知；
- 数据与安全：备份与恢复、存储空间、诊断与反馈；
- 应用：语言、外观、关于工程印记。

每行可显示简短当前状态，例如存储占用、语言和定位策略。危险操作不放在设置首页，仍在对应项目或记录中处理。

## 8. 视觉与动效规则

导航、搜索、项目卡片、设置分组和操作面板采用半透明玻璃材质。玻璃组件必须设置最低背景不透明度、边框和文字对比度；复杂照片背景上增加实色遮罩。设备性能不足时允许降低或关闭实时模糊，但不能改变布局。

- 品牌色继续使用浅绿色，红色只用于危险操作和错误；
- 页面转场控制在 220–280ms，不同时叠加大幅缩放、位移和透明度；
- Hero 只用于照片查看链路；
- 列表滚动不重复播放入场动画；
- 卡片和按钮只提供轻微按压缩放及墨水反馈；
- 开启系统“减少动画”后跳过非必要过渡；
- 所有交互目标保持可触达尺寸，文字缩放后不得遮挡关键操作。

## 9. 加载、空状态与错误

项目、项目记录和全部记录统一使用稳定的骨架占位，骨架数量根据可视区域生成，真实数据出现后不得短暂显示虚假的多条卡片。

空项目、无筛选结果、无照片和归档状态分别提供明确说明与可执行入口。照片处理、权限、备份和恢复失败必须显示具体原因及下一步操作，不只显示“失败”。

页面刷新只更新发生变化的卡片，不能因单张照片状态变化重建整页或重播页面动画。

## 10. 验收要求

自动化测试至少覆盖：

- 一级 Dock 切换及页面状态保留；
- 返回键退出搜索、筛选、编辑、批量模式和弹层；
- 全选与取消全选；
- 筛选标签、底部筛选面板及日期分组；
- 拍摄字段复用、定位提示消失和后台状态刷新；
- 成片/原图、双页签、Hero 和相邻照片滑动；
- 加载、空状态、错误说明、大字体、窄屏和减少动画模式。

实现完成后必须通过 Flutter 静态检查和全部测试、Rust 格式检查与测试、Android 单元测试及 debug APK 构建，并在真机重点检查玻璃可读性、列表滚动、返回逻辑和照片转场。

## 11. 不在本次范围

- 不修改现有照片水印内容与文件命名规则；
- 不修改备份文件格式、恢复契约或项目生命周期规则；
- 不新增云同步、账号体系和在线服务；
- 不重新处理历史照片；
- 不直接调整发布版本号，版本计划在实施阶段单独确认。
