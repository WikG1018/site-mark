# 工程印记核心稳定化设计

## 目标

在不扩大产品边界的前提下，修复当前拍摄后台队列与项目备份链路中会导致“界面提示成功但任务或文件尚未真正安全落地”的问题，并补齐下一次发布所需的自动化门禁。

本设计仅覆盖下一次稳定性补丁。用户已明确要求：**不修改 Android 自动备份、设备迁移、`allowBackup`、`dataExtractionRules` 或相关隐私承诺。**

## 范围

### 包含

- 拍照完成后先确认 WorkManager 已接受任务，再向用户显示“已加入后台处理”。
- 首次调度失败时保留原图与记录，显示“处理启动延迟”，并由定位协调器在当前会话重试调度。
- 定位尚未完成时，后台任务以“等待定位、任务正常结束”收口，避免占用重试预算；定位完成后再次唤醒处理。
- 后台调度入口兜住数据库、Rust 初始化、处理器和数据库关闭阶段的异常。
- 项目详情的单项目导出进入与设置页相同的备份预检，不再绕过处理中/失败记录检查。
- 备份先写临时文件，成功后在同一文件系统原子重命名为唯一正式文件；失败保留旧备份并清理本次临时文件。
- Android 使用系统文档创建器把 ZIP 流式复制到用户选择的位置；取消选择不得提示“备份完成”。
- 保留“分享”作为已生成备份的次要操作。
- 用户界面使用稳定的错误类别和可操作文案，不展示底层异常、堆栈或平台错误字符串。
- 发布工作流校验标签、`pubspec.yaml` 版本、main 提交关系、Release 签名、APK 版本/ABI/权限和两个 APK 的证书一致性。

### 不包含

- Android 自动备份或设备迁移策略。
- 云同步、账号、自研相机、图库导入、iOS、应用商店上架。
- 记录全文搜索、分页、数据库重构、全屏大图渐进解码等后续 `0.9.x` 工作。
- 一次性拆分 `AppDatabase`、Rust 图像核心或备份服务的大型重构。

## 方案比较与选择

### 拍摄队列

1. **立即注册任务并等待注册结果（采用）**：只等待轻量的 WorkManager 注册，不等待定位、渲染或相册发布。定位完成后再注册一次幂等唤醒任务。
2. 等定位完成后再注册：实现简单，但重新引入数秒等待，不符合连拍目标。
3. 把定位完全移入后台任务：无法使用拍摄按钮触发的前台一次性定位结果，改变既定证据语义。

`workmanager_android 0.9.0+2` 已将 Dart 的 `ExistingWorkPolicy.append` 映射到 Android `APPEND_OR_REPLACE`，因此保留现有串行链策略，只修正文档和异常收口。

### 备份外部落地

1. **Android Storage Access Framework 流式保存（采用）**：不把大 ZIP 整体读入 Dart 内存，由 Kotlin 在 I/O 线程流式复制到用户选择的文档 URI。
2. `FilePicker.saveFile(bytes: ...)`：API 简单，但需要把整个 ZIP 读入内存，不适合包含大量原图的工程备份。
3. 继续只使用分享面板：无法可靠区分取消与真实保存，也不能证明文件已离开应用私有目录。

## 组件与数据流

### 拍摄

1. 系统相机返回有效原图。
2. 数据库记录变为 `captured`，相机目标被正式保留。
3. 前台调用 `scheduler.enqueue(captureId)`：
   - 成功：返回 `queued`；
   - 失败：返回 `delayed`，不把记录错误地改成永久失败。
4. 定位协调器在后台解析 EXIF/一次性前台定位；无论记录此前是否已解析，都可执行带退避的队列唤醒。
5. 后台任务若看到 `locationResolution == pending`，返回 `deferred` 且任务本身成功结束；定位完成后的第二次唤醒再进入渲染。
6. 启动恢复仍按“相机恢复 → 定位恢复 → 队列恢复”兜底。

### 备份

1. 所有可恢复项目备份都进入 `ProjectBackupService` 预检。
2. 为本次操作生成唯一 ID、正式路径和同盘临时路径。
3. Rust 把单项目 ZIP 或多项目 bundle 写入临时路径并返回摘要。
4. Dart 文件系统适配器把临时文件原子重命名到正式路径。
5. Android 打开 `ACTION_CREATE_DOCUMENT`，用户确认后在 I/O 线程复制 ZIP。
6. 返回 `saved`、`cancelled` 或失败：只有 `saved` 才显示外部保存完成；取消时保留本次应用内 ZIP，允许再次保存或分享。

## 错误处理

- 相机、调度、原图缺失、原图被修改、处理失败采用固定错误代码；界面按当前语言显示“发生了什么、原图是否保留、下一步怎么做”。
- 原始异常仅用于本地控制流，不写入记录卡片、SnackBar 或诊断包。
- 调度器初始化和队列注册失败保持可重试；定位后台重试使用有限次数和短退避。
- 临时备份在异常路径主动删除；进程被杀留下的导出临时目录在下次启动清理。
- 系统文档选择器取消属于正常取消，不计为失败，也不显示成功。

## 测试与验收

- 调度注册成功前不得返回 `queued`；注册失败返回 `delayed`，记录保持可恢复。
- 定位已解析记录也能再次触发队列唤醒；首次唤醒失败后可在当前会话重试成功。
- 后台看到待定位记录不增加处理次数、不返回 WorkManager retry。
- 项目详情备份入口必须使用统一备份页面并预选当前项目。
- 处理中记录阻止导出；失败记录只有明确确认后遗漏，manifest 计数准确。
- 新备份失败不覆盖任何既有备份，正式路径不留下半成品。
- Android 保存取消不显示完成；保存成功、保存失败和再次保存分别有测试。
- Flutter、Rust、Kotlin 全量测试、`flutter analyze`、Debug APK 和 unsigned Release APK 构建通过。
- Release 工作流对标签版本不一致、非 main 标签和未签名 APK 失败。
