# SiteMark 备份恢复、项目管理与定位提示设计

## 目标

本次改动解决三个相互关联的使用问题：

1. 将首页难以理解的“导入项目备份”图标迁移到设置中的独立“备份与恢复”菜单，并同时提供单项目与多项目备份。
2. 为项目增加重命名和删除能力。
3. 移除拍摄表单中长期占位的定位说明，只保留首次需要时出现、可关闭且授权后自动消失的提示。

不改变 SiteMark 无账号、无云端、离线优先的产品边界，也不自动扫描用户存储空间。

## 一、设置中的“备份与恢复”

### 信息架构

在首页总设置增加二级菜单“备份与恢复”，路由为 `/settings/backup-restore`。页面包含两个入口：

- **备份项目**：进入项目选择页。
- **恢复项目**：先显示简短说明，再调用 Android 系统文件选择器选择 ZIP。

首页右上角现有“导入项目备份”图标移除。项目详情中的单项目导出入口继续保留，方便用户在查看项目时快速导出；它与设置中的统一备份入口调用同一套服务。

### 备份项目

项目选择页使用复选列表，支持单选、多选、全选和取消全选，并显示已选项目数量。用户继续后统一选择是否包含应用私有原图：

- 选择一个项目时，生成现有兼容格式的单项目 ZIP。
- 选择多个项目时，生成一个 SiteMark 多项目备份 ZIP。

多项目备份包采用外层清单加独立项目归档的结构：

```text
bundle.json
projects/<project-id>.zip
```

`bundle.json` 标明应用标识、格式版本、创建时间、项目数量和每个内部归档的 SHA-256。每个内部 ZIP 继续使用现有单项目备份格式，从而复用已经验证的照片、项目设置、定位数据和原图校验逻辑。

生成完成后调用系统分享面板，用户可以保存到下载目录、网盘或其他应用。应用不把备份绑定到固定目录。

### 恢复项目

恢复页面在打开文件选择器前说明：请选择由 SiteMark 导出的单项目或多项目备份 ZIP；普通照片分享 ZIP 不能恢复。

选择文件后的流程：

1. 识别单项目备份或多项目备份包。
2. 在写入数据前完成格式、文件数量、解压大小、路径、清单和 SHA-256 校验。
3. 显示恢复预览：项目名称、照片数量、原图情况和水印设置情况。
4. 对现有重名项目自动生成可用名称；用户可以在确认前逐项修改。
5. 显示按项目和照片计算的恢复进度。
6. 完成后返回项目首页，新项目由现有数据库监听自动显示。

多项目恢复采用整包事务语义：任一项目失败时，删除本次已经创建的项目、数据库记录和应用私有文件，不留下部分恢复结果。恢复过程写入持久化待处理标记；应用被终止后，下次启动继续执行清理，避免半恢复项目出现在首页。

恢复后的照片不自动重新发布到系统相册。用户可在项目记录编辑模式中使用现有“再次保存”功能发布。跨项目多选导出的普通分享 ZIP 仍不可恢复。

### 限制与错误提示

保留现有单项目归档限制，并为多项目包增加项目总数、照片总数、单文件大小、总解压大小和嵌套层级限制。错误提示至少区分：

- 不是 SiteMark 备份；
- 备份版本不支持；
- 备份损坏或校验不一致；
- 选择的是普通分享 ZIP；
- 存储空间不足；
- 项目名称冲突；
- 恢复失败且已完成回滚。

## 二、项目重命名与删除

### 入口

项目详情页右上角增加项目操作菜单，包含：

- 重命名项目；
- 删除项目。

记录编辑按钮仍只负责进入或退出记录多选模式，避免与项目管理混淆。

### 重命名

重命名对话框预填当前名称，并沿用新建项目的名称规则：忽略首尾空白、连续空白和英文大小写检查重名，同时检查安全文件名冲突。

重命名只改变项目当前显示名称和之后新拍照片使用的项目名前缀。已有记录的照片编号、JPEG 文件名、原图路径、水印照片和历史水印内容全部保持不变，避免破坏追溯关系。项目更新时间随重命名更新。

### 删除

删除前显示不可逆确认对话框，明确列出项目名称、记录数量、私有原图数量，以及以下处理结果：

- 删除项目数据库记录；
- 删除该项目在应用私有目录中的原图、缓存和未发布文件；
- 取消或安全忽略该项目仍在等待的后台处理任务；
- 保留已经保存到 Android 系统相册的水印照片；
- 保留用户已经导出到应用外部的 ZIP 备份。

不提供“同时删除相册照片”选项，也不主动操作系统相册中的既有照片。删除成功后返回项目首页并显示完成提示；文件清理失败时不得静默删除数据库后丢失重试依据，应保留可恢复的清理标记并在启动恢复流程中重试。

## 三、拍摄页定位提示

删除拍摄表单底部固定显示的“拍摄前仅请求一次前台位置；拒绝授权也可以继续拍摄”卡片。

保留现有顶部定位授权说明卡片，并遵循以下规则：

- 首次进入拍摄页且定位未授权、用户也未关闭过提示时显示；
- 用户点击“开启定位”并授权后立即消失，后续不再显示；
- 用户拒绝授权后仍可继续拍摄；
- 用户点击关闭后持久化关闭状态，后续拍摄页不再显示；
- 永久拒绝时，“开启定位”引导到系统设置；
- 用户以后需要调整时，可从设置中的“定位”菜单进入，不依赖拍摄页重复提醒。

拍摄按钮本身继续保持不触发权限弹窗：只有用户主动点击提示卡片中的“开启定位”时才请求授权。

## 数据与兼容性

- 数据库需要新增项目重命名接口，但无需改变现有照片编号或文件结构。
- 多项目备份使用新的外层格式版本；现有 v1、v2 单项目备份继续支持恢复。
- 已发布的相册照片不属于项目删除事务，删除项目后仍可在系统相册查看。
- 新增的待清理标记必须与现有导入中断恢复机制协调，启动清理异常不得阻断相机、定位和后台队列恢复。

## 验证要求

### 自动化测试

- 设置页显示“备份与恢复”，首页不再显示恢复图标。
- 单选、多选、全选和取消全选行为正确。
- 单项目备份保持原格式兼容；多项目备份清单、内部哈希和恢复结果正确。
- 多项目恢复发生中途失败时完整回滚；进程中断后启动清理可重试。
- 重命名拒绝显示名和安全文件名冲突；新照片使用新名称，旧照片编号和路径不变。
- 删除项目清理应用内数据和私有文件，但不调用系统相册删除接口。
- 删除过程中断或文件失败时保留待清理标记。
- 定位固定提示不再渲染；首次提示、关闭持久化、授权后隐藏和设置跳转行为保持正确。
- 中英文文案、返回行为和 360dp 宽度布局通过组件测试。

## 明确不包含

- 云端同步、自动备份、定时备份和账号体系；
- 自动扫描下载目录并列出备份；
- 修改或批量重命名历史照片文件；
- 删除已经保存到系统相册的照片；
- 将普通跨项目分享 ZIP 当作可恢复备份。
