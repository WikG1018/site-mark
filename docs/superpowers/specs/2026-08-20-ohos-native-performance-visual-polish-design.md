# SiteMark 鸿蒙原生版流畅度与视觉完善设计

> 状态：设计已确认，待实施计划。
>
> 目标分支：`ohos-native`。实现分支和 PR 均不得以 `main` 或 `ohos` 为目标。
>
> 视觉方向：A「克制工程感」，全局统一。

## 目标

在不增加产品功能、不修改水印算法和备份格式的前提下，完成两类提升：

1. 大量工程记录下，列表、图片查看和页面切换保持稳定流畅。
2. 首页、列表、详情、设置与表单使用一致、克制、易辨识的鸿蒙原生界面。

## 不做

- 不修改 Android/Flutter 产品代码。
- 不修改数据库结构、备份 ZIP 契约、照片编号或水印版式。
- 不增加云同步、账号、自研相机或新的业务入口。
- 不做无关的大规模重构，也不以“清零所有 DevEco 警告”为目标。
- 不宣称完成 HarmonyOS NEXT 真机性能验收；当前仍以 DevEco 模拟器为验收环境。

## 已确认设计

### 1. 全局视觉基线

- 首页标题使用 22–24fp；详情标题使用 20–22fp。标题、说明和操作按钮不再争抢同一行宽度。
- 英文长标题允许响应式缩短、换行或让次要操作降级为图标，不能再出现关键信息被省略。
- 主操作使用实色品牌绿；次操作使用浅色表面；普通操作文本化；危险操作只使用低饱和红色表面。
- 搜索框和表单字段统一使用可见容器、边框、焦点态和不小于 44vp 的点击高度。
- 减少胶囊按钮的重复使用。卡片、分段控件、筛选和状态标签各有独立层级。
- 悬浮 Dock 保留，但降低视觉重量；列表底部按 Dock、批量操作栏和系统安全区动态留白。
- 浅色、深色、中文、英文和大字体使用同一布局规则。

### 2. 页面调整

| 页面 | 调整 |
| --- | --- |
| 项目首页 | 缩短首屏；搜索与生命周期切换明确成组；项目卡保留最多三张预览图 |
| 全部记录 | 搜索、筛选、日期和选择入口组成紧凑工具区；记录卡统一信息层级 |
| 项目详情 | 项目摘要压缩；项目操作分级；记录列表与首页共用同一记录卡 |
| 记录详情 | 图片占用合理首屏高度；水印成片/原图切换依附图片；元数据集中成组 |
| 设置 | 使用分组表面和统一行高；最后一项不能被 Dock 遮挡 |
| 拍摄与编辑表单 | 输入框可见；必填、提示、错误和辅助说明层级明确 |
| 批量选择 | 继续使用悬浮玻璃操作栏，但图标必须配文字且不得压缩可选择区域 |

### 3. 公共组件

扩充 `UiTokens`，集中维护字号、间距、圆角、表面颜色、按钮高度、阴影和底部安全区。复用或新增以下小组件：

- `AppTopBar`
- `AppSearchField`
- `LifecycleSegment`
- `FilterToolbar`
- `ProjectCard`
- `CaptureCard`
- `FloatingDock`
- `BatchActionBar`
- `AppFormField`
- `InlineErrorPanel`

只拆分本轮实际涉及的超大页面文件。页面负责状态和导航，组件负责显示，分页数据源负责加载；三者不能继续混在同一个结构中。

## 性能与数据流

### 1. 长列表

- 项目列表、全部记录、项目内记录及设置中的项目选择列表统一使用懒创建数据源。
- 数据库继续使用现有游标分页和索引；默认每页最多 50 条，不一次读取全部记录。
- 数据源保存稳定 ID、下一页游标、加载状态和查询代次。
- 搜索、筛选或项目变化时递增查询代次；旧请求返回后必须被丢弃。
- 触底加载采用单次执行，同一页不能重复请求或重复插入。
- 已加载内容在追加失败时继续显示，列表底部提供重试，不把整页替换成错误页。

### 2. 全屏查看器

- 禁止进入查看器后循环读取项目全部照片。
- 查看窗口最多保留当前照片及前后各两张，共五条记录。
- 当前照片按屏幕所需像素解码，长边上限 2048px；相邻预览长边上限 1024px。
- 同时只保留一张全尺寸解码结果。记录移出窗口后立即释放页面持有的图片引用。
- 到达窗口边缘时按当前排序方向补取相邻记录；没有相邻记录时停止加载。
- Hero/共享转场只使用当前照片，不允许为整批记录预先创建共享转场图片。

### 3. 列表图片

- 缩略图按实际显示尺寸和设备像素比例请求，长边不得超过 1024px。
- 列表不得直接持有原始全分辨率图片，也不得增加无上限的应用级图片缓存。
- 图片加载期间显示固定尺寸占位，成功后轻量淡入；失败时显示稳定占位和重试入口。
- 图片失败不能闪出“失败”文字、透明底或旧照片。

### 4. 页面状态

- 搜索、筛选和滚动位置在页面返回后恢复。
- 页面离开、查询变化或组件销毁后，异步结果不能继续写入旧页面状态。
- 非当前页面停止非必要动画、图片预载和分页请求。
- 内存压力较高时，依次释放查看器相邻预载、缩略图引用和非当前查询结果；不得中断水印处理队列。

## 动效与无障碍

- 正常模式统一页面、Dock、筛选和批量栏的动画时长与曲线，避免多个动画叠加。
- 遵循系统“减少动画”设置：关闭非必要位移、缩放和实时模糊，只保留必要状态反馈。
- 图标按钮、卡片、选择框、Dock 项和图片切换必须具有可读名称、角色、选中状态和禁用状态。
- 所有主要点击区域不小于 44vp。
- 大字体下允许标题和说明换行；操作按钮、状态标签和列表卡不得裁切关键信息。
- 文字和图标对比度需在浅色、深色模式分别人工检查。

## 错误处理

- 首次加载失败：显示局部错误面板和重试，不显示空白页。
- 追加页失败：保留已有数据，只在列表底部提示。
- 图片失败：显示占位并允许重试，不影响元数据和操作按钮。
- 查看器补页失败：当前照片继续可看，左右滑动边界暂时停止并提供重试。
- 旧异步请求、重复触底和离开页面后的回调均为幂等无效操作。
- 任何视觉优化失败都不能改变照片状态、文件路径或后台水印队列。

## 测试与验收

### 自动化

- 懒加载数据源：首屏、追加、去重、查询代次、重复触底、失败重试和销毁后回调。
- 查看窗口：首张、末张、中间张、连续滑动、补页失败和窗口最大五条。
- 图片策略：列表尺寸上限、当前/相邻解码级别、离开窗口释放和失败占位。
- 页面状态：搜索、筛选、滚动恢复与系统返回。
- 无障碍和减少动画策略的纯逻辑测试。
- 现有 ArkTS、Rust、Flutter 回归测试继续全部通过；debug HAP 构建成功。

### 模拟器验收

- 使用 2,000 条模拟记录检查快速滚动、连续触底、筛选切换和详情往返。
- 连续进入/退出全屏查看 20 次，记录基线、峰值和退出后内存；不得持续单向增长。
- 核对中文/英文、浅色/深色、普通/大字体、正常/减少动画。
- 核对空态、骨架加载、局部失败、图片失败、批量选择和底部安全区。
- 保存本轮关键页面截图，更新 `ohos-native/docs/deltas.md` 中仍需真机确认的性能边界。
