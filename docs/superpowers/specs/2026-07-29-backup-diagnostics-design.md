# SiteMark 空白项目备份与本地诊断设计

日期：2026-07-29  
状态：已确认方案，待实施
目标版本：`0.8.0+11`

## 1. 目标

本次只解决两类问题：

1. 空白项目可以正常备份和恢复；备份不能静默遗漏处理中或失败的记录。
2. 在“设置”增加“诊断与反馈”，本地循环记录最近问题，用户主动生成诊断包后才能分享。

不增加联网、自动上传、账号、云端日志或第三方统计 SDK。

## 2. 当前问题与根因

当前 `ProjectExportService` 只导出 `ready` 状态的记录，并在没有 `ready`
记录时抛出 `Project has no completed captures to export`。备份界面只识别
存储空间不足，其他异常统一显示“无法生成备份”。

因此会出现两种问题：

- 空白项目备份必然失败，但界面不说明原因。
- 项目同时包含已完成和未完成记录时，未完成记录可能被忽略，用户却不知道备份不完整。

## 3. 备份行为

### 3.1 备份前检查

用户选择项目后，服务必须重新读取项目及其全部记录，并生成结构化检查结果。界面不得解析
英文异常字符串判断业务状态。

| 项目状态 | 行为 |
| --- | --- |
| 没有任何记录 | 允许备份，显示“0 张记录，将备份项目资料和水印设置” |
| 全部记录已完成 | 正常备份 |
| 存在等待、处理中记录 | 阻止本次备份，列出项目名称和数量，提示稍后重试 |
| 存在失败记录 | 列出项目名称和数量，提供“返回处理”和“仅备份已完成记录” |
| 项目已被删除 | 中止并提示重新选择项目 |
| 存储空间不足 | 中止并提示清理空间后重试 |

“仅备份已完成记录”不是默认选项。用户必须在明确看到遗漏项目和遗漏数量后主动确认。
备份完成提示再次写明遗漏总数，避免用户误认为备份包含全部记录。

检查结果只代表备份开始时的快照。开始导出前服务再检查一次项目存在性和记录状态；新拍照片
发生在快照之后时，不纳入本次备份，并在备份清单中记录快照时间。

### 3.2 空白项目归档

单项目归档升级为 schema v3。v3 允许 `photos` 为空，并保存：

- 项目名称；
- 项目说明；
- 项目创建时间；
- 项目水印位置、透明度、强调色、字体大小；
- 备份创建时间和记录快照时间；
- 完整/部分备份标记，以及已完成、处理中、失败记录数量；
- 空的 CSV 记录表和空照片清单。

恢复空白项目时创建一个没有拍摄记录的正常项目，并恢复上述资料。v1、v2 备份继续兼容；
旧格式的读取规则不放宽，新生成的 v3 才允许零照片。

多项目备份包可以同时包含空白项目和有照片项目。空白项目仍计入项目数量和进度。
恢复预览遇到部分备份时必须显示归档中记录的遗漏数量，不能把部分备份呈现为完整项目。

### 3.3 结构化结果

备份服务返回明确的结果类型，而不是向界面暴露底层异常文本：

- `complete`：完整备份；
- `partial`：用户确认后只备份已完成记录，并附遗漏数量；
- `blockedProcessing`：存在等待或处理中记录；
- `projectMissing`：项目在操作中被删除；
- `insufficientStorage`：空间不足；
- `ioFailure`：文件创建或分享失败；
- `invalidState`：其他不应出现的内部状态。

底层原始错误只写入脱敏诊断记录，用户界面显示原因和下一步操作。

## 4. 诊断与反馈

### 4.1 设置入口

在设置一级菜单增加：

`设置 → 诊断与反馈`

页面包含：

- 页面顶部持续显示隐私保护说明卡片；
- 本地记录状态：默认开启、保留最近 7 天、上限 2 MB；
- 最近一次异常的时间和分类；
- “查看诊断摘要”；
- “生成并分享诊断包”；
- “清除诊断记录”；
- 明确列出诊断包“包含什么”和“不包含什么”。

隐私保护说明必须直接写明：

> 诊断记录只保存在本机，不会自动上传。诊断包不包含照片、项目名称、工程内容、
> 拍摄人、位置坐标或原图路径；只有你主动点击分享后，文件才会交给系统分享面板。

该说明不能只藏在弹窗或二级说明中。生成诊断包前再显示一次包含/不包含清单并要求确认。

应用不提供关闭本地记录的开关。记录体积固定受限，且不包含业务内容；始终记录才能保留偶发
故障发生前后的证据。只有用户主动点击分享，文件才会交给 Android 系统分享面板。

### 4.2 记录内容

允许记录：

- 应用版本、构建号；
- 手机厂商、型号、Android/API 版本、系统语言；
- 应用私有目录剩余空间和各类文件总量；
- 相机目标准备、记录落库、请求启动系统相机等阶段耗时；
- 相机返回结果：完成、取消、失败；
- 后台任务入队、开始、重试、成功、失败及耗时；
- 记录状态数量：等待、处理中、完成、失败；
- 备份、恢复、项目删除的开始、结果、耗时和数量；
- 权限状态：已授权、拒绝、永久拒绝，不记录权限数据本身；
- 经过白名单映射的错误分类和错误代码。

采集这些信息不新增 Android 权限。

禁止记录：

- 照片、缩略图、原图或水印图；
- 项目名称、项目说明；
- 工程部位、工作内容、拍摄人、备注；
- 经纬度、地址或 EXIF；
- 原图路径、文件名、照片编号；
- 原图 SHA-256；
- 用户选择的分享目标；
- 完整堆栈或可能包含路径、项目内容的原始异常文本。

### 4.3 本地存储

诊断事件采用带 schema 版本的 JSON Lines。写入前只接受固定字段和枚举值，业务层不能传入
任意文本。前台与后台写入通过文件锁串行化，单条事件一行；进程中断造成的末尾残行在读取时
直接丢弃。

日志按 7 天和 2 MB 双重限制轮转。超过任一限制时优先删除最旧事件。清除操作删除全部诊断
日志和已生成但尚未分享的诊断 ZIP，不影响照片、项目、备份或数据库。

诊断失败不得阻塞拍照、后台处理、备份、恢复和删除。所有记录调用均为尽力而为。

### 4.4 诊断包

诊断 ZIP 包含：

- `summary.txt`：中文可读摘要；
- `environment.json`：应用、设备、系统和存储概况；
- `events.jsonl`：最近 7 天的脱敏事件；
- `manifest.json`：诊断格式版本、生成时间和文件校验值。

生成前显示隐私确认页。用户确认后创建 ZIP 并打开系统分享面板。诊断包不自动上传，也不写入
系统相册。新生成成功后清理旧诊断 ZIP，只保留最近一个。

## 5. 组件边界

- `ProjectBackupPreflightService`：读取项目状态并返回结构化检查结果。
- `ProjectExportService`：按已确认快照生成 schema v3 单项目归档。
- Rust 归档层：写入/读取 v3，允许 v3 零照片，继续读取 v1/v2。
- `DiagnosticRecorder`：校验事件字段、加锁写入和轮转。
- `DiagnosticBundleService`：收集环境快照、生成诊断 ZIP、清理旧包。
- `DiagnosticsScreen`：展示摘要、隐私边界、分享和清除操作。

各组件通过结构化对象通信，不把平台异常字符串作为业务判断依据。

## 6. 错误与恢复

- 备份检查后项目状态变化：停止并要求重新检查，不生成可能误导的完成提示。
- 用户取消分享：备份或诊断包仍已成功生成，提示可再次分享，不标记为生成失败。
- 诊断包生成失败：保留原日志，提示检查存储空间后重试。
- 日志损坏：忽略无效行并在摘要中记录“已跳过损坏事件数量”，不影响应用启动。
- 后台进程写入冲突：文件锁等待设短超时；超时则放弃该条事件，不等待核心任务。

## 7. 自动化验证

### 7.1 备份

- 空白项目导出和恢复往返测试；
- schema v3 项目说明、创建时间和水印设置往返测试；
- v1、v2 备份兼容测试；
- 多项目包混合空白和有照片项目；
- 等待、处理中记录阻止备份；
- 失败记录必须明确确认后才能部分备份；
- 部分备份结果包含准确遗漏数量；
- 项目在检查后被删除时安全失败；
- 中英文错误提示和 360 dp 布局测试。

### 7.2 诊断

- 每种事件只接受允许字段；
- 项目名称、坐标、路径、照片编号、哈希和原始异常不会进入日志或 ZIP；
- 7 天与 2 MB 轮转；
- 并发写入、文件锁超时和末尾残行；
- 清除日志不影响业务数据；
- 诊断写入失败不影响拍照和后台处理；
- 诊断 ZIP 文件清单、manifest 校验和旧包清理；
- 设置路由、返回逻辑、分享取消和存储不足提示。

## 9. 完成标准

- 空白项目可以完整备份并恢复。
- 任何未包含在备份中的记录都经过用户明确确认。
- 所有备份失败均说明原因和下一步操作。
- 设置中可以查看、生成分享和清除诊断数据。
- 诊断页和生成前确认均明确展示隐私保护说明。
- 诊断包默认本地记录、7 天/2 MB、无业务敏感内容、无自动上传。
- 自动化测试和构建通过，版本号与文档保持一致。
