# SiteMark 1.0 发布后优化设计

> **状态：** 已批准（会话设计评审 2026-08-06）  
> **版本语境：** `v1.0.0` **已经发布**（`1.0.0+15`）；GitHub Release 可能仍标 Pre-release。  
> **方法：** Superpowers brainstorming → 本规格 →（批准后）writing-plans → 分 PR 实现。  
> **非目标：** 本文件不是实施计划；不授权自动 merge / 改 Release 标记 / 打 tag。

## 1. 背景

SiteMark 是离线优先的 Android 工程水印相机。产品边界与决策见：

- `docs/current-product-architecture.md`
- `docs/decision-records.md`
- `docs/release-checklist.md`
- `docs/verification-v1.0.0-device.md`（真机回归勾选）

在途相关 PR（规格撰写时，头提交以远端为准）：

| PR | 主题 | 在本规格中的角色 |
| --- | --- | --- |
| #36 | Agent / 文档入口 | WP-DOC / MERGE |
| #35 | 导入错误映射 + 删除诊断 | WP-DATA / MERGE |
| #37 | 恢复诊断 + 真机清单 + integration CI | WP-DATA / FIELD / MERGE |
| #34 | 根切换动效 + 玻璃 | WP-UX（P1） |

用户选定优化主题：**现场可靠（1）+ 数据路径安全（2）为 P0**；**体验与性能（4）为 P1**。  
推进方式：**规格先行（B）**——先定边界与验收，再写实施计划；合并为计划中的显式任务且需人工授权。

## 2. 目标

1. **P0 现场可靠**  
   - 真机回归以 `docs/verification-v1.0.0-device.md` 为勾选源。  
   - 明确：何时可去掉 Pre-release 标记、何时应发 `1.0.1`（与「代码已合并」解耦）。

2. **P0 数据路径安全**  
   - 备份 / 恢复 / 删除：用户可见错误不泄漏私有路径与原始异常。  
   - 诊断事件覆盖备份、恢复、删除（枚举级；无工程内容/路径/坐标/堆栈），且与真实 UI 入口一致。  
   - 启动删除清理不得把「仅存在、项目仍在的 marker」记成 success。

3. **P1 体验与性能**  
   - 动效/玻璃在可读性与合成成本可控前提下可合入（以 #34 及审查修复为准）。  
   - 根分支 Offstage 保活策略有文档化观察项；不默认拆保活。

4. **过程**  
   - 规格 → 实施计划 → 分 PR；YAGNI；不扩大产品边界。

## 3. 非目标

- 不新开：图库导入、云同步、账号、自由拖拽水印、内置相机、iOS。  
- 不做无 analyze/测试门禁的全库 Theme/const 机械优化。  
- 不把 workmanager 0.9→0.10 大版本升级绑进本规格，除非 P0 被其阻塞。  
- 不在本规格中授权：自动 merge、创建/修改 GitHub Release、上传签名密钥、force-push `main`。  
- 不为拆文件而拆：仅当大文件阻碍 P0/P1 且有测试护栏时，允许局部拆分。

## 4. 成功标准

| 级别 | 标准 |
| --- | --- |
| 规格 | 本文件无 TBD；维护者书面认可 |
| 计划 | `writing-plans` 产出任务清单，每任务有测试/验收命令 |
| P0 代码 | 错误映射与诊断隐私有自动化锁定；无已知用户可见路径泄漏 |
| P0 现场 | 真机清单 §0 ≥2 类厂商有记录；§2/§4 无未解释失败（人工） |
| P1 | 体验改动不引入内容可读性回退；内存以观察或低风险缓解为主 |
| 发布决策 | 有「保持 Pre-release / 去标记 / 发 1.0.1」的书面决定与依据 |

## 5. 工作流与阶段

```text
本规格 → 维护者批准 → writing-plans
  → 分 PR 实现（聚焦测试）
  → code review
  → 维护者授权后 merge / 改 Release 标记 / 打 tag
```

| 阶段 | 名称 | 内容 | 退出条件 |
| --- | --- | --- | --- |
| 0 | 基线对齐 | main 与在途 PR 头；规格+计划认可 | 规格与计划已批准 |
| 1 | 合入已修 PR | 顺序 **#36 → #35 → #37 → #34**（需授权） | 已合或明确延期有记录；CI 绿 |
| 2 | P0 数据收口 | 合入后入口/诊断/文案审计；补测 | 自动化覆盖映射+诊断隐私 |
| 3 | P0 现场 | 执行真机清单；填结果 | §0/2/4 有记录；阻塞项入库 |
| 4 | 发布决策 | Pre-release 标记 / 1.0.1 | 书面决策（可「待真机」） |
| 5 | P1 体验 | #34 后观感；内存观察；可选小缓解 | 不阻塞阶段 4 |

阶段 2 与 3 可并行；阶段 5 不阻塞阶段 4。

### 门禁

| 门禁 | 规则 |
| --- | --- |
| PR 合入 | CI 绿 + Important 审查项已处理 + **维护者明确授权 merge** |
| 去掉 Pre-release 标记 | 真机关键路径有记录 + **维护者明确授权** |
| 打 `v1.0.1` | release-checklist 自动化 + 本规格 P0 相关证据 + **维护者明确授权** |

### CI 与真机

| 类型 | 角色 |
| --- | --- |
| 默认 PR CI | 挡合并 |
| Integration（夜间/手动） | 不挡 PR；失败当信号 |
| 真机清单 | P0 现场唯一权威；禁止用 CI 冒充真机通过 |

## 6. 工作包（任务地图）

### WP-DOC — 文档与过程

- 本规格与后续实施计划。  
- Agent 入口、release checklist、真机清单与「1.0 已发布」一致。  
- 合入后消除互相矛盾的诊断/版本表述。  
- **验收：** 无「尚未发 1.0」误导；入口指向 architecture + decision-records。

### WP-MERGE — 在途 PR 合入

- 顺序：**#36 → #35 → #37 → #34**。  
- 冲突解决：  
  - `docs/release-checklist.md`：保留 Agent 链接 + 「v1.0.0 已发布」+ 真机清单链接。  
  - `lib/app.dart`：deletion 与 bundle 的 diagnostics 接线并存。  
  - README 诊断表述与**已接线代码**一致。  
- **不做：** 未授权 merge、改写发布 tag。

### WP-DATA — 数据路径安全（P0）

| 子包 | 目标 | 自动化方向 |
| --- | --- | --- |
| D1 用户错误 | 无路径、无原始异常拼接 | 中英映射单测 |
| D2 删除诊断 | success / cascade fail；cleanup 跳过仍存在项目 → blocked | deletion 诊断测 |
| D3 恢复诊断 | Settings 恢复路径事件完整 | restore 诊断测 |
| D4 入口一致 | 诊断挂在真实入口 | 抽检 / 必要 widget 测 |
| D5 合入后审计 | 扫泄漏与文档超前 | grep + 文档 |

诊断字段仅限：category、outcome、code、count、durationMs（及既有无敏感字段约定）。

### WP-FIELD — 现场可靠（P0）

- **F1** 清单源：`docs/verification-v1.0.0-device.md`。  
- **F2** 矩阵：≥2 类厂商。  
- **F3** 关键路径：连拍≥10、杀进程/重启队列、备份恢复、删除不删相册。  
- **F4** 决策记录：清单 §8/§9。  
- **执行者：** 人工；Agent 不伪造真机结论。

### WP-UX — 体验与性能（P1）

- **U1** 动效/玻璃（#34 及审查修复：overlay 在内容下、opacity clamp）。  
- **U2** 根分支内存文档 + 真机观察。  
- **U3** 仅有证据时的低风险缓解（单独小 PR）。  
- **不做：** 手指横滑切页；无证据大拆 Offstage；第二层全屏实时模糊堆叠。

### 依赖关系

```text
WP-DOC → WP-MERGE → WP-DATA
                ↘
                 WP-FIELD → 发布决策
                              ↘
                               WP-UX（不阻塞决策）
```

## 7. 测试策略

| 层级 | 用途 |
| --- | --- |
| 单元 / Widget | 错误映射、诊断隐私、cleanup 口径、glass 层级 |
| 既有 workflow 测试 | 备份/导入/删除不回归 |
| Integration workflow | 信号，不挡 PR |
| 真机清单 | P0 现场权威 |

## 8. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 四 PR 合入冲突 | 固定顺序 + 冲突解决规则 |
| 真机无人执行 | 表可空；决策标待真机；不伪造通过 |
| 文档超前代码 | 合入后 D5；文案跟接线走 |
| P1 抢 P0 | 阶段门禁 |
| 范围膨胀 | 非目标清单；新想法新规格 |

## 9. 建议时间盒（示意）

| 窗口 | 焦点 |
| --- | --- |
| 第 1 周 | 计划；授权后 MERGE |
| 第 2 周 | DATA + 启动真机 |
| 第 3 周 | 真机填表 + 阻塞分类 |
| 第 4 周 | 发布决策；P1 小步 |

## 10. 留给实施计划的内容

以下**不**在本规格写死，由 `writing-plans` 展开：

- 每任务精确文件、命令、提交边界  
- workmanager 大版本是否进 1.0.1  
- `v1.0.1` 最终版本号与 changelog 文案  
- 真机执行人与机型排期  

## 11. 一句话

在**不扩产品边界**的前提下，用**规格 → 计划 → 分 PR**推进：先对齐文档与合入已修 PR，再锁数据路径安全与真机证据，然后做发布决策；体验性能跟进但不挡 1.0 维护出口。
