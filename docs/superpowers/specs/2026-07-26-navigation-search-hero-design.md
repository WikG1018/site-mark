# 导航、搜索与图片飞行稳定性设计

## 目标

修复三个使用体验问题：记录详情返回时图片闪烁、首页搜索有两个取消动作且标题跳动、返回按钮偶尔跳过刚才的页面。

## 导航规则

用户主动进入下一级页面时使用 `context.push(...)`，使系统返回和 AppBar 返回都只退回刚才所在页面。适用范围包括项目详情、拍摄记录详情、编辑记录、拍摄表单、项目水印设置和应用设置二级页。

仅在操作已经完成且需要明确落点时使用 `context.go(...)`：保存项目、保存记录编辑、删除记录、首页顶级目的地切换，以及完成拍摄后需回到指定项目的场景。取消编辑或系统返回不写入数据，只执行 `pop`。

## 图片详情转场

保留记录缩略图到详情大图的 Hero 飞行效果。Hero 飞行层使用固定、无淡入的图片显示：同一个图片提供者、`gaplessPlayback: true`，不包含 `AnimatedSwitcher` 或 `Image.frameBuilder` 的透明度动画。

详情页路由仍保持 300ms 横向层级转场，但不对该路由叠加透明度动画。这样页面具有方向感，Hero 也能在返回时稳定落回原缩略图，避免不同解码尺寸、图片淡入和页面淡出同时交接造成闪烁。

全屏图片查看的缩放、平移和下拉关闭保持现有行为，不在本次改动范围内。

## 首页搜索

搜索状态仅保留一个右侧关闭按钮：有输入内容时先清空输入；输入为空时退出搜索。标题和搜索框在相同的 AppBar 标题布局中切换，不使用会改变宽度或重排的交叉淡入；退出搜索后“工程印记”位置稳定。

## 验收

- 从拍摄记录打开详情并返回，图片仍有飞行效果，落回缩略图时无闪白或跳帧。
- 搜索时只显示一个取消按钮；首次点击清空内容，第二次点击退出搜索；标题位置不跳动。
- 编辑记录点返回只取消编辑并回到记录详情；详情点返回回到原记录列表；表单点返回回到所属项目。
- 保存、删除等已完成操作仍到达预期业务页面。
- 覆盖新增路由语义、搜索状态、Hero 飞行组件的 widget 测试，并通过现有 Flutter 分析与测试。
