# 鸿蒙原生版差异与验证边界

更新：2026-08-20。本表只记录 HarmonyOS 原生版相对 Android v1.0.8 的平台差异和尚未完成的设备级验证。业务规则、数据安全规则和用户可见结果不以“平台不同”为由静默降级。

| 能力 | 当前实现/结论 | 对用户的处理 | 转正条件 |
| --- | --- | --- | --- |
| 系统相机 | 产品使用 CameraPicker；API 22 x86_64 模拟器不能返回有效结果 | 调试构建在 `applicationInfo.debug` 为真时注入内置 JPEG 驱动状态机；release 不进入该通道 | HarmonyOS 真机完成拍摄、取消、旋转、杀进程恢复回归 |
| 后台处理 | 应用存活时串行处理；被系统结束后在下次启动收敛 | 不显示“系统结束后仍会继续”的错误承诺 | 真机验证后台生命周期后更新说明 |
| 相册保存 | 后台处理先完成应用私有水印成片；记录详情的“保存到相册”使用系统确认面板 | 需要用户交互的系统面板不阻塞连拍；详情即时显示“未保存/已保存” | 真机验证确认、拒绝、重复保存和目标相册行为 |
| 相册删除 | 模拟器返回权限拒绝 | 删除应用记录不连带承诺删除相册；拒绝时保留并提示 | 真机验证系统删除确认流 |
| 动态取色 | 使用工程印记固定强调色与深浅色资源 | 不宣称与 Android Monet 动态取色完全等价 | 平台提供稳定等价能力后评估 |
| 性能 | 模拟器只做功能和基本滚动走查 | 不宣称低端机/高像素真机性能 | 真机完成长列表、50MP 图片、内存压力回归 |
| 安装包签名 | 本地可产出并安装 unsigned/debug HAP | PR 只提供可复现构建，不提交私钥 | 使用发布证书签名并完成覆盖安装测试 |
| 自动化 CI | GitHub 公用 runner 不预装可再分发的 DevEco/HarmonyOS SDK | PR CI 检查 manifest 最小权限、双 ABI 配置及 `ohos-native` Rust feature；ArkTS/HAP 使用本地 DevEco 证据 | 提供合规的专用 runner 后补充 HAP 远程构建 |
| 设备性能 | 已确认模拟器界面交互与单张串行处理，不代表真机性能 | 列表图片限尺解码、复用稳定 key、全分辨率处理不经 ArkTS 字节数组 | 在真机上完成长列表、12/50MP、连拍和内存压力回归 |

任何新增差异必须先进入本表，再进入发布说明；不允许用原始平台异常字符串替代可理解的用户提示。
